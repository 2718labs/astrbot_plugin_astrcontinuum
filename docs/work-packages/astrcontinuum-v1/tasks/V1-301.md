# V1-301 Standalone Read View, Retrieval, Budget, and Assembly Trace

Owner: runtime-read-agent

Depends on: V1-203

## Goal

Build the standalone request-side runtime that converts exactly one durable
`RequestView` into a bounded, deterministic, explainable provider projection. The
runtime must use only AstrContinuum-owned Snapshot, Capsule, and Journal data; it must
not write durable state, wait for background work, call AstrBot, call Sylanne, or call a
remote model.

card implements only a bounded deterministic structured-and-lexical fallback over the

## Runtime Contract

- `read_request_view(source, session_key)` delegates to
  `source.read_request_view(session_key)` exactly once, validates the returned immutable
  identity and coverage relation, and returns it without opening another connection.
  Repository errors remain explicit; V1-302 owns host fail-open behavior.
- Define a narrow canonical `TokenCounter` protocol with `count_text(text) -> int`.
  Production assembly accepts an injected counter. Any bundled conservative fallback
  must overestimate safely and must never use `len(text) // 4` as a ceiling.
- Public immutable DTOs include explicit configuration, candidate blocks, block
  rejection records, assembly result, and assembly trace. Trace contains ids, slots,
  token counts, scores, reasons, Snapshot/pointer/C/H, and budget arithmetic. It contains
  no message text, Capsule prose, query text, current input, or opaque payload.
- `select_candidates(view, query, config)` uses only AC-owned structured Capsule fields,
  exact anchors, dependencies, entities, decisions, and bounded raw Delta. Active goals,
  hard constraints, raw Delta, and exact anchors are represented independently of
  `narrative_summary`. Query and candidate traversal are bounded by configuration.
- Retrieval order and ties are deterministic. Scores and weights are explicit
  configuration. Selected decisions carry their rationale, alternatives,
  supersession, rejection reason, and dependency context in the same block.
- Opaque third-party input enters assembly only as a non-negative integer token cost.
  No API in this task accepts opaque text, embeddings, semantic labels, source ids, or
  stable hashes.
- Compute:

  ```text
  B_input = min(
      target_input_budget,
      hard_input_ceiling,
      model_context_limit - reserved_output_and_tools
  )
  B_required = current_input_cost + fixed_required_cost + safety_margin
  B_AC = max(0, B_input - opaque_token_cost - B_required)
  ```

- Normal assembly fills `B_AC` in the frozen priority order: active goals and hard
  constraints; raw Delta; exact anchors; recent raw suffix; active task Capsules;
  relevant evidence; episode/global background. A block is selected at most once.
- If required AC material does not fit, enter `EMERGENCY_ASSEMBLY`. Preserve whole
  critical blocks in the same deterministic order and the most recent raw suffix that
  fits; reject the rest with stable reasons. Never exceed `B_input`, mutate the
  `RequestView`, or advance durable coverage.
- Projected text may contain selected AC-owned block text. Trace and exceptions must
  remain content-free and identify only stable ids/reasons.
