## Repository Contract

- Export `SQLiteRepository` plus closed, immutable result DTOs and stable repository
  exceptions. Physical lookup/hash/JSON columns never appear as extra wire fields.
- All accepted datetimes are timezone-aware and are normalized before persistence to one
  fixed-width UTC `Z` representation so SQLite ordering is chronological.
- Capture validates or creates the exact `SessionKey`, resolves
  `(session_key_hash, source_hook, idempotency_key)` before sequence allocation, returns an
  exact duplicate, and rejects a key reuse whose immutable request differs. Allocation and
  append share one immediate transaction, so rollback cannot burn a sequence.
- Request view fixes the active pointer, pointed committed Snapshot, Journal high-water
  `H`, and ordered `C < sequence <= H` Delta in one read transaction. Bootstrap returns
  logical empty base data, never a fabricated Snapshot row.
- Intent raising max-folds `intent_target_high_water_mark`; it never changes an active
  attempt's frozen target. Claiming is single-winner, refreshes the base pointer, freezes
  the current intent target, increments epoch and attempt, and establishes a bounded
  lease.
- Every worker mutation matches job id, owner, epoch, eligible state, and unexpired lease.
  A stale fence changes zero durable rows and raises a stable repository error.
- Failure persists a complete redacted error tuple, enters `RETRY_WAIT` or `FAILED`, and
  clears the effective lease atomically. Recovery requeues expired working jobs, preserves
  epoch, and also clears a `READY_TO_COMMIT` candidate id.
- Publication loads the durable base, source Delta, and candidate inputs under the fence,
  then calls the permanent validator. Within one savepoint it inserts new Capsules, the
  committed Snapshot, and ordered membership in this physical order:
  `capsules -> snapshot -> snapshot_capsules`. This order satisfies immediate foreign
  keys; all three logical candidate stages remain in the same savepoint before pointer
  CAS.
- Bootstrap and existing-pointer CAS require strict coverage advance. Same-prefix
  uniqueness or pointer CAS loss rolls the savepoint back completely, then records only
  the fenced job as `SUPERSEDED`. A stale fence is not a publish conflict and must roll
  back the entire operation.
- Both publication terminal branches preserve higher intent as fresh or retained
  `PENDING` work against the winning active Snapshot and pointer version.
