# Capsule Recomposition Matrix 实验设计

日期：2026-07-30

状态：书面规格已完成自审，等待用户复核

## 1. 问题与边界

AstrContinuum 需要验证一种纯 Capsule 上下文管理架构。Summary 只作为离线公平基线，不属于运行时组件或回退。系统不把完整历史当作运行时依赖，只维护当前 Capsule 与一个有界 delta，并周期性执行：

\[
\mathcal R_B(C_t,\Delta_t;\Theta)\rightarrow(C_{t+1},L_t,E_t)
\]

其中：

- \(C_t\) 是当前 Capsule 状态；
- \(\Delta_t\) 是尚未并入 Capsule 的有界增量；
- \(B\) 是持久状态字节预算；
- \(\Theta\) 是固定版本的确定性权重；
- \(L_t\) 是本次重编排的溯源映射；
- \(E_t\) 是明确释放的语义集合；
- \(C_{t+1}\) 是唯一可供后续查询读取的新代。

允许部分语义损失，但错误、冲突或陈旧事实被当作当前事实的代价必须远高于明确遗漏。系统宁可表示“不知道”，也不生成无来源或状态不明的断言。

本设计仅用于实验。现有生产永久校验要求旧 active 语义与 active anchors 无损保留，并要求完整质量门禁；因此有损候选不得发布，不得伪造质量字段，也不得修改生产校验器来放行。

## 2. 非目标

- 不建设长期事件日志或权威历史存储。
- 不使用 Summary 作为运行时上下文、回退或重建来源。
- 不接本地模型、远程模型 API 或真实聊天。
- 不在本轮修改 `astrcontinuum/`、存储迁移、发布路径或 AstrBot 集成。
- 不在第一阶段训练权重模型。
- 不以单一高压缩倍数证明语义质量。

## 3. Capsule 状态与连续性内核

每一代 Capsule 分为：

\[
C_t=K_t\oplus E_t
\]

- \(K_t\)：连续性内核，保证任务主线不会突然断开；
- \(E_t\)：弹性正文，承载可压缩、可合并、可释放的非核心语义。

### 3.1 连续性内核角色

`KernelSchemaV1` 至少包含以下角色：

1. 当前根目标；
2. 当前焦点或任务阶段；
3. 下一项未闭环事项；
4. 当前有效硬约束；
5. 最新仍有效的已确认决定；
6. 当前任务必需的精确锚点；
7. `as_of` 高水位与生成版本等控制元数据。

每个角色具有固定槽位数、单项字节上限和总字节上限。该配置在实验清单中预注册，其最大合法序列化尺寸定义为预算单位 \(K\)。只有主 Capsule 方法实现连续性内核；所有预算化方法共享数值相同的 \(B\)，因此 Summary 不能获得额外字节。超过角色配额时，按固定的角色优先级、有效状态、显式确认、修订序号和 stable ID 进行确定性取舍。

主实验生成器保证所有 gold-critical 内核项都落在预注册槽位容量内，避免通过缩小“核心”定义制造虚假成功。超过槽位容量的独立 overflow 场景只用于 admission 与降级测试，不进入主非劣推断。

内核不是永久记忆。每一代都从 \(K_t\oplus E_t\oplus\Delta_t\) 重新计算 \(K_{t+1}\)。已完成目标、已撤销决定和失效约束可被替换或释放；系统只保留当前连续性主线。

### 3.2 内核硬约束

- 所有适用的内核角色必须在新代中有且只有一个无冲突的规范表达，允许固定配额的多值角色除外。
- 每个保留项必须可追溯到当前 Capsule 或本轮 delta。
- 当前状态与历史状态必须显式区分；无法安全标注时删除历史项。
- 必需精确锚点不得被近义改写。
- 在 \(B=K\) 时，\(E_{t+1}\) 为空，但 \(K_{t+1}\) 仍必须完整。
- 初始配置 \(B<K\) 时实验不得启动。运行中提出 \(B<K\) 的预算变更时，该变更不生效；状态进入 `ADMISSION_BLOCKED`，当前 \(K_t\) 继续受上一有效预算约束，并拒绝接纳新 delta。系统不得生成空 Capsule。

## 4. 语义原子与候选

Atomizer 把旧 Capsule 与 delta 解析为语义原子：

\[
a_i=(type,status,time,polarity,provenance,exactness,dependencies)
\]

候选生成器只允许四类操作：

- 原样保留；
- 有覆盖证明的合并；
- 不改变关键限定词的缩写；
- 明确释放。

候选不得凭空创造事实。合并候选只有在其每个输出断言都能映射到输入原子，并保留时间、状态、否定和精确性要求时，才具有覆盖关系。

## 5. Capsule Recomposition Matrix

CRM 使用以下矩阵和向量：

- \(F\)：语义特征矩阵，包含类型、状态、热度、时间、精确性和依赖特征；
- \(A\)：原子到候选的可验证覆盖矩阵；
- \(R\)：候选间冗余矩阵；
- \(H\)：不可同时成立的候选冲突矩阵；
- \(D\)：原子依赖矩阵；
- \(b\)：候选真实 UTF-8 序列化字节数；
- \(e\)：候选错误或歧义风险；
- \(w=F\theta\)：遗漏各原子的损失；
- \(x\)：候选选择向量；
- \(z\)：原子保留向量。

主要目标为：

\[
\min_{x,z}
w^\top(1-z)+\gamma e^\top x+\rho x^\top R x
\lambda_{\mathrm{churn}}L_{\mathrm{churn}}
\lambda_{\mathrm{kernel}}L_{\mathrm{kernel}}
\]

其中错误风险系数 \(\gamma\) 的量级必须显著高于普通遗漏代价。连续性内核不是可购买的软收益；其覆盖损失 \(L_{\mathrm{kernel}}\) 必须为零，否则候选不可提交。

硬约束包括：

\[
\sum_c b_cx_c\le B
\]

\[
x_c\le g_c
\]

\[
z_i\le\sum_c A_{ic}x_c
\]

\[
z_i\le z_j\quad\text{if }a_i\text{ depends on }a_j
\]

\[
x_c+x_d\le1\quad\text{if }H_{cd}=1
\]

并且：

- 所有内核角色满足覆盖与精确性要求；
- 总错误风险不超过固定上限；
- 所有输入原子均被标记为保留、合并或释放；
- 相同输入、预算、权重版本和策略必须产生相同语义哈希。

完整优化是 NP-hard。实验实现采用确定性两级求解：

1. 删除未通过门控或被其他候选严格支配的候选；
2. 按边际保留价值减错误与冗余代价后的单位字节收益排序；
3. 每次选择后补齐依赖闭包并检查冲突和风险；
4. 对缩小后的候选池使用固定变量顺序的精确求解复核；
5. 求解超时则使用同一固定排序的安全贪心结果，不改变硬约束。

一般冲突图和二次冗余项下不宣称贪心具有 \(1-1/e\) 保证。

## 6. 数据流与接口

数据流为：

1. 读取冻结的 \(C_t\) 与截至高水位 \(H_t\) 的有界 \(\Delta_t\)；
2. Atomizer 生成带状态、时间和来源的原子；
3. Candidate Composer 生成保留、合并、缩写和释放候选；
4. Matrix Builder 构造 \(F,A,R,H,D,b,e\)；
5. CRM Optimizer 选择 \(K_{t+1}\oplus E_{t+1}\)；
6. Loss-aware Gate 校验预算、溯源、内核、依赖、冲突、风险和确定性；
7. 通过后执行生成指针的原子交换；
8. 释放 \(C_t\)、已消费 \(\Delta_t\)、候选池、矩阵和临时文本。

实验接口采用纯计算形态：

```python
recompose_capsule(
    base_state,
    delta,
    byte_budget,
    loss_policy,
    weight_version,
) -> RecompositionResult
```

`RecompositionResult` 至少包含：

- 新 Capsule 状态；
- retained、merged 与 released 原子 ID；
- coverage、dependency 与 conflict 诊断；
- 持久字节数、目标函数值和求解状态；
- omission、error、stale-current 与 continuity 报告；
- 权重版本、矩阵哈希和语义哈希；
- `NORMAL`、`KERNEL_ONLY` 或 `ADMISSION_BLOCKED` 状态；
- 生产永久校验的只读诊断及 `strict_eligible` 标志。

`strict_eligible=false` 的结果只进入实验指标，不调用生产发布路径。

## 7. 请求水位与查询投影

回答请求 \(q_n\) 时，历史状态冻结在当前请求之前的已提交高水位。当前用户输入是查询，不先写入用于回答自己的历史 Capsule。完成该轮交互后，它才进入下一段 bounded delta。

本实验在每个 generation checkpoint 先完整消费该代 delta、提交新 Capsule，再冻结哈希并揭示隐藏查询。因此查询阶段不存在尚未并入 Capsule 的可读 delta。未来若要支持持续流式运行，可另行设计 bounded recent-delta lane；它不属于本实验，不能在本轮暗中加入。

查询路径为：

\[
q\rightarrow\Pi_q(C_{t+1})\rightarrow\text{bounded injected context}
\]

投影器只能读取冻结后的 \(C_{t+1}\)，不得读取：

- 被释放的旧 Capsule；
- 已消费或尚未授权的 delta；
- 候选池与临时矩阵；
- 离线真值；
- Summary 基线。

若冻结 Capsule 中没有可验证支持，投影结果必须明确表示上下文不足。查询投影不能修改 Capsule，也不能把查询结果写回同一代。

## 8. 原子交换、释放与失败状态机

状态机为：

`FRESH -> DIRTY -> BUILD -> READY -> COMMIT -> FRESH`

正常候选不可行时依次执行有界降级：

1. 正常 CRM；
2. 仅使用直接可验证、低风险候选的 safety-first CRM；
3. `KERNEL_ONLY`，释放全部弹性正文；
4. 若请求的新预算 \(B<K\)，拒绝该预算变更并进入 `ADMISSION_BLOCKED`；保持上一有效预算下的当前内核且不积累新 delta。

新代只有在门禁通过且指针交换成功后才成为可读状态。交换前失败时旧代仍有效，且不得释放。连续失败达到固定重试上限后，只保留当前内核并阻止继续接纳 delta，因此失败不会演变成无限存储。

交换成功后只持久保留：

- 新 Capsule；
- 生成号、水位、权重版本和内容哈希；
- 不含被释放原文的聚合损失统计。

被释放的原文、旧 Capsule、已消费 delta 和临时矩阵不得成为后续查询输入。实验离线真值位于独立评分侧，运行时进程不可访问；它用于测量遗漏与错误，不是 Capsule 的重建来源。

## 9. 后学习

第一阶段使用固定的 \(\theta_0\)，以权重版本和矩阵哈希保证确定性。运行只记录不含释放原文的特征与结果：

- 特征分布和候选统计；
- 后续查询是否使用到保留原子；
- 明确遗漏、错误、陈旧误报；
- 持久字节、投影字节、耗时和 churn；
- 内核角色覆盖与降级状态。

后学习阶段可离线求解：

\[
\theta_{k+1}=\arg\min_\theta
\sum_t(
\lambda_oL_{\mathrm{omission}}+
\lambda_eL_{\mathrm{error}}+
\lambda_bL_{\mathrm{bytes}}+
\lambda_cL_{\mathrm{churn}})
+\alpha\|\theta\|_2^2
\]

其中 \(\lambda_e\gg\lambda_o\)。学习只允许更新软权重，不能改变内核角色、预算下限、来源门禁、依赖闭包、冲突规则、错误上限、确定性 tie-break 或释放顺序。

## 10. 实验协议

### 10.1 数据与隔离

- 24 条确定性合成事件流；
- 每条 12 代 delta；
- 每代冻结后揭示 6 个隐藏查询；
- 每条流包含冲突更新、话题回返、精确锚点、硬约束、决定、未闭环事项和无关干扰；
- 总固定分母为每个方法、每个预算 \(24\times12\times6=1728\) 个状态查询单元；
- 查询、gold 与评分契约在压缩前对运行时不可见；
- 先冻结状态语义哈希，再向查询执行器释放查询；
- 不使用模型或人工语义裁判，使用确定性 claim-v2 与精确字段判定。

离线 canonical truth 只属于生成器和评分器。CRM、旧 Capsule、Summary 与查询投影器均不能把它当运行时历史读取。

### 10.2 方法与公平基线

主方法：

- CRM + 连续性内核 + 查询投影。

基线：

- Legacy Capsule 递归压缩；
- Recursive Summary，仅离线运行；
- 未压缩 canonical state，仅作为质量上界，不参与缓存替代。

消融：

- 用标量单位字节贪心替代完整 CRM；
- 保留 CRM 但移除查询投影；
- 移除连续性内核，作为离线失败对照，不作为可发布方案。

所有压缩方法在同一条件下共享：

- 相同持久 UTF-8 字节预算；
- 相同查询注入字节预算；
- 相同事件流、高水位、隐藏查询和固定分母；
- 相同状态冻结顺序。

Summary 只能从其冻结文本中选择查询片段，不能访问源事件或 Capsule。Capsule 投影器同样只能读取冻结 Capsule。

### 10.3 预算与轮次

预注册连续性内核字节上限为 \(K\)。预算轴为：

\[
B\in\{8K,4K,2K,1.5K,K\}
\]

主推断点为第 12 代、预算 \(2K\)。其余预算和中间代用于 rate-distortion、退化路径和稳健性分析。

另执行两种压力测试：

1. 在每个预算下对冻结 Capsule 做 16 轮 zero-delta 重编排；主方法所有轮次的语义哈希必须与起点一致。Legacy Capsule 与 Recursive Summary 执行对应的递归重压缩链，其漂移作为对照报告，不构成主方法的放宽条件；
2. 对第 12 代状态从 \(8K\) 逐级压至 \(K\)，验证非核心语义逐步释放而连续性内核不发生断裂。

### 10.4 指标

压缩与释放：

\[
CR_{\mathrm{history}}=
\frac{\text{截至当前水位的累计 canonical 输入字节}}
{\text{当前持久 Capsule 字节}}
\]

\[
CR_{\mathrm{step}}=
\frac{|C_t|+|\Delta_t|}
{|C_{t+1}|}
\]

同时报告：

- 单轮释放率；
- \(K/E\) 字节占比；
- kernel-only 与 admission-blocked 发生率；
- 查询投影注入字节；
- 重编排峰值工作内存；
- 矩阵构造、求解、门禁和总耗时。

语义与安全：

- 加权语义保留率与明确遗漏率；
- continuity break rate；
- stale-current assertion rate；
- 核心角色覆盖率；
- 必需精确锚点 exact-match；
- 隐藏查询 claim-v2、atomic、dedup 和 query-level 正确率；
- 话题回返正确率；
- 冲突、依赖和来源门禁失败率；
- 跨代 churn；
- zero-delta 语义哈希稳定率。

判定定义：

- `continuity break`：截至水位 \(H_t\) 的任一适用 gold-critical 内核角色缺失、矛盾、时间状态错误，或无法在固定查询注入预算内由冻结 Capsule 恢复；
- `stale-current assertion`：输出把截至 \(H_t\) 已被 superseded、retracted 或更高 revision 替换的原子陈述为当前有效；
- `明确遗漏`：没有支持时返回上下文不足，不产生替代性猜测；
- `核心角色覆盖`：按预注册 KernelSchemaV1 与独立 gold 标签计算，不以输出自身声明为真值。

压缩率不得单独解释。所有压缩曲线必须与遗漏、错误、连续性和查询质量位于同一图组或相邻面板。

### 10.5 统计

- 事件流 cluster 是唯一独立推断单位；
- 1728 个查询单元是固定报告分母，不当作独立样本；
- 使用配对 cluster bootstrap 计算方法差值的置信区间；
- 结构、预算、门禁或运行失败使该 checkpoint 的 6 个查询全部计入失败；
- 明确未知计为遗漏，不计为错误；
- 陈旧或错误断言同时计为回答失败和安全失败；
- 主结论只使用预注册的 \(B=2K\)、第 12 代端点；
- 其他预算、轮次与消融标为次要或探索性分析。

### 10.6 成功与停止条件

在所有 \(B\ge K\) 的主方法运行中必须满足：

- continuity break 为 0；
- stale-current assertion 为 0；
- 适用内核角色覆盖为 100%；
- 必需精确锚点为 100%；
- 字节预算超限为 0；
- Summary、旧代或离线真值回退为 0；
- zero-delta 语义哈希稳定为 100%。

在主推断点 \(B=2K\)、第 12 代：

- CRM 相对 Recursive Summary 的隐藏查询正确率差，单侧 95% 配对 cluster-bootstrap 下界不低于 -5 个百分点。

在 \(B=K\)：

- 允许非核心问题出现明确遗漏；
- 所有内核问题仍必须可回答；
- 不允许输出空上下文。

任一 continuity break、stale-current 误报、必需锚点错误、Summary 回退或预算超限均是当前架构的硬失败，不得被总体平均值掩盖。

## 12. 允许的结论

若全部硬门禁和主推断条件通过，可声明：

> 在预注册的确定性合成多轮工作负载与字节预算下，CRM Capsule 能作为独立上下文缓存运行，在释放旧代的同时保持连续性，并在主端点达到对递归 Summary 的预设非劣标准。

不得外推为：

- 已证明真实聊天或开放域语义质量；
- 已证明模型抽取能力；
- 已完成生产迁移；
- 已证明任意预算下无损；
